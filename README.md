# Telegram chat · GREEN-API

Небольшой текстовый чат в стиле Telegram Web: подключение своего инстанса GREEN-API, поиск получателя по телефону, отправка и получение сообщений. Реализован на React, TypeScript (strict), Vite, native fetch и CSS Modules. Проверки: ESLint, Prettier и Vitest. Без backend и глобальной библиотеки состояния.

## Запуск

Требуется Node.js 22.12+ или 24+.

```bash
npm install
npm run dev
```

Откройте локальный адрес, напечатанный Vite.

```bash
npm run lint
npm test
npm run build
npm run format:check
npm run preview
```

`npm run format` форматирует исходники. `npm run preview` обслуживает предварительно собранный `dist`.

## Подключение GREEN-API

1. Создайте **Telegram**-инстанс в [личном кабинете GREEN-API](https://console.green-api.com/) и авторизуйте в нём Telegram. Состояние должно быть `authorized`.
2. При необходимости отметьте «Установить настройки для получения сообщения» (по умолчанию выключено). Только с отмеченным чекбоксом приложение отправляет `SetSettings` с `webhookUrl: ""`, `outgoingWebhook: "yes"`, `stateWebhook: "yes"`, `incomingWebhook: "yes"`. Это заменяет ранее заданный webhookUrl получением через HTTP API. Без отметки запрос настроек не отправляется: сохраняются текущие настройки инстанса, сброса к заводским значениям нет.
3. В форме приложения введите только `idInstance` и `apiTokenInstance` из кабинета. По умолчанию используется `https://4100.api.green-api.com`, как в [официальном Telegram SDK](https://github.com/green-api/telegram-api-client-python/blob/master/telegram_api_client_python/API.py). Если в кабинете указан другой `apiUrl`, раскройте «Дополнительные настройки» и укажите его. Это необязательное поле; адрес должен быть HTTPS-хостом GREEN-API без пути.
4. Введите телефон получателя с кодом страны и нажмите «Открыть чат». Пробелы, скобки и дефисы допускаются. `CheckAccount` определяет Telegram `chatId`; сообщения и ответы сопоставляются по этому ID, а не по номеру телефона.
5. Отправьте текст и ответьте из Telegram получателя. Ответ должен появиться автоматически. Enter отправляет текст, Shift + Enter вставляет перенос строки.

При отмеченном чекбоксе после проверки реквизитов приложение сохраняет настройки уведомлений и ожидает их применения и состояния `authorized`, проверяя готовность каждые 5 секунд (до 5 минут). При ошибке подключения форма остаётся открытой; автоматического повтора `SetSettings` нет. Для получения сообщений используйте один потребитель очереди: не открывайте тот же инстанс в нескольких вкладках или других HTTP API-клиентах одновременно.

## Архитектура

- `src/api/greenApi.ts` — явные методы API, таймауты, отмена запросов и проверка используемых полей ответа.
- `src/api/notification.ts` — преобразование текстовых уведомлений в модель сообщения.
- `src/api/pollNotifications.ts` — последовательный long polling: чтение → обработка → подтверждение через DELETE. Следующий запрос запускается через `setTimeout`, после завершения предыдущего. Временные ошибки повторяются с задержкой от 2 до 30 секунд; ошибки реквизитов останавливают цикл до переподключения.
- `src/hooks/useMessages.ts` — чаты, отправка, дедупликация входящих сообщений по паре chatId/idMessage и жизненный цикл запросов.
- `src/components/` — формы подключения и получателя, список сообщений, поле ввода и раскладка чата.
- `src/utils/validation.ts` — нормализация телефона и адреса API.
- `tests/` — тесты отдельно от исходников, с разделением по назначению:

```text
tests/
├── api/          # Контракты API, уведомления и polling
├── components/   # Подключение и переключение чатов (jsdom)
└── utils/        # Валидация и нормализация ввода
```

`npm test` запускает все тесты. Например, `npm test -- tests/api` запускает только проверки API. Типы тестов проверяются отдельным `tsconfig.test.json`, включённым в `npm run build`.

Учётные данные, сообщения и чаты хранятся только в памяти React. Выход или обновление страницы очищает их. Токен не сохраняется в localStorage, `.env` или логах; браузер при этом всё равно имеет доступ к реквизитам и запросам. Разрешены HTTPS-хосты `green-api.com` и его поддомены; перенаправления запросов запрещены.

## Ограничения и проверка

- Только текст и текстовые уведомления с URL. Прочие типы уведомлений подтверждаются и пропускаются. Повреждённые текстовые уведомления остаются в очереди, а ошибка показывается в интерфейсе.
- История Telegram не загружается. Входящая очередь GREEN-API может содержать сообщения за последние 24 часа; после подтверждения они удаляются из очереди и не восстановятся при перезагрузке страницы.
- Статус «В очереди GREEN-API» означает принятие запроса API, а не доставку или прочтение. Статусы доставки и сообщения, отправленные из других клиентов, пока не синхронизируются.
- При сетевой ошибке текст остаётся в поле ввода, а отправка отмечается как неподтверждённая. Автоматического повтора отправки нет: сервер мог принять сообщение до разрыва соединения. Перед повтором проверьте Telegram.
- Поиск по телефону может не работать из-за настроек приватности получателя или лимитов Telegram.
- Черновик поля ввода сбрасывается при переключении чата. Входящие сообщения других чатов сохраняются в памяти текущего сеанса.
- Нужен современный браузер с `fetch`, `AbortSignal.any`, `AbortSignal.timeout` и `crypto.randomUUID`; при размещении используйте HTTPS. Доступность GREEN-API из браузера зависит от CORS сервера и сети; серверный прокси в проект не добавлен.

Тесты используют только фиктивные данные и mock API. Они проверяют контракты запросов, нормализацию, mapping уведомлений, порядок подтверждения, отмену, StrictMode cleanup и восстановление polling. **Реальный обмен с Telegram и браузерный сценарий ещё не проверены.**

Для ручной проверки подключите свой инстанс, откройте чат, отправьте сообщение и получите ответ. Затем временно отключите сеть и восстановите её: получение должно возобновиться без дублей. Проверьте пустую отправку, Enter/Shift+Enter, смену чата и выход во время запроса. В DevTools после выхода не должно появляться новых запросов к GREEN-API.
